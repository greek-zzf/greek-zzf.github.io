Songless catalog map · Web + iOS

哪首歌从哪来
Deezer · iTunes · Apple Music

分类 / Daily / Unlimited / Survival / Singer 走 Deezer。艺人、艺人 Mix、艺人搜索走 Apple 体系。 关键分叉：Web 用公开 iTunes Search API（itunes.apple.com）， App 用 MusicKit Apple Music Catalog（api.music.apple.com）。 两者不是同一个接口。

两套曲库 API vs 拼接 每个模式 搜索怎么做

1. 两套曲库，一条规则

按「这局歌从哪抽」分，不要按产品名混。Apple 在 Web 和 App 上不是同一条路。

Deezer

分类曲库

Daily、Unlimited、Categories、All Songs、Survival、Guess the Singer / Artist、Archive、分类挑战。曲目来自打包好的 Deezer playlist ID。

https://api.deezer.com/search?q=
https://api.deezer.com/playlist/{id}
https://api.deezer.com/playlist/{id}/tracks
https://api.deezer.com/track/{id}
iTunes Search Web only

Web 艺人曲库

Artist、Mix、艺人搜索、Artist Fan Challenge。浏览器或服务端直接打公开 Search / Lookup，不走 Apple Music Catalog。

https://itunes.apple.com/search
  ?term=...&entity=song|musicArtist
https://itunes.apple.com/lookup?id=
Apple Music App only

iOS 艺人曲库

Artist、Mix、艺人搜索。经 MusicKit MusicDataRequest 打 Catalog，需要 MusicKit 授权，不是拼接 iTunes 链接。

https://api.music.apple.com/v1/catalog/{sf}/search
https://api.music.apple.com/v1/catalog/{sf}
  /artists/{id}/view/top-songs

2. 哪些是 API，哪些是拼接链接

「拼接」= 把 path / query / 回调名 / 图片尺寸写进 URL。预览 MP3 从不自己拼，一律用接口返回的 preview / previewUrl。

用途 端 类型 实际怎么打
Deezer 搜索 / 列表 / 单曲 Web 服务端 API GET https://api.deezer.com{path}。path 是拼出来的（/search?q=、/playlist/248297032），但是标准 REST。失败再打 RapidAPI 同源 path：https://deezerdevs-deezer.p.rapidapi.com{path}。
Deezer 搜索 / 列表 / 单曲 Web 浏览器 JSONP 拼接 Deezer 没有 CORS。前端把 URL 拼成 https://api.deezer.com/search?q=yellow&output=jsonp&callback=dzcb_...，插 <script src>。2 秒超时或失败，再 fetch 自家 /api/deezer?action=search&q=。
Deezer 搜索 / playlist tracks iOS API 设备直连 api.deezer.com。搜索 /search?q=&limit=25；分类 /playlist/{id}/tracks?limit=100。没有 JSONP，也没有 RapidAPI。
iTunes 搜歌 / 搜艺人 / lookup Web API new URL('https://itunes.apple.com/search') 再 searchParams.set(term/entity/limit/country)。客户端组件直接 fetch；也有服务端代理 /api/itunes?action=artist_songs|artists|artist_lookup。
Apple Music 搜歌 / 搜艺人 / Top Songs iOS API URLComponents 拼 Catalog path，真正发请求的是 MusicKit MusicDataRequest，不是裸 URLSession 无鉴权。
iTunes 封面放大 Web 拼接 接口给 artworkUrl100，正则把 /100x100bb.jpg 换成 /1200x1200bb.jpg。
Apple Music 封面尺寸 iOS 拼接 Catalog 给模板 .../{w}x{h}bb.jpg，本地把 {w}{h} 替换成 600 或 1200。
Deezer 封面 两边 API 字段 用返回的 cover_xl → cover_big → cover_medium → cover，不改尺寸字符串。
试听 MP3 两边 API 字段 Deezer preview（带 hdnea=exp=，约 15 分钟过期）；iTunes previewUrl；Apple Music attributes.previews[].url。过期时 Web 再 GET /track/{id} 刷新。
Songless 游戏接口 两边 自家 API songless.pro/api/game/... 和 /api/party/...。只负责 Daily 权威关卡、成绩、挑战链接、Party Demo 资格，不出艺人曲库。

Deezer 浏览器这条链路（Web 特有）

输入 "yellow"
  → 拼 path  /search?q=yellow
  → 拼 JSONP https://api.deezer.com/search?q=yellow&output=jsonp&callback=dzcb_m8k2
  → document.head.appendChild(<script src=...>)
  → 失败 / 超时
  → GET /api/deezer?action=search&q=yellow
       → 服务端 GET https://api.deezer.com/search?q=yellow
       → 再失败 → RapidAPI 同源 path

3. 每个模式：选歌 + 搜索

同一玩法在 Web / App 上曲库来源可能不同。搜索分两种：远程搜目录，或在已经拉下来的艺人曲池里本地过滤。

Daily · 今日谜题

WebDeezer 选歌
  • 服务端 ensureDailyChallenge。当天还没有就从固定 playlist 池抽一首写入数据库。
  • playlist 顺序：md5(日期:playlist-order) 决定从哪张列表开始。
  • 曲目下标：md5(日期:playlistId:track) % 可播放数。同一天全服同一首。
  • 日语站换日本市场 playlist。preview 快过期时 GET /track/{id} 刷新。
  • 前端只 GET /api/game/daily?locale=，不自己抽。
搜索
  • 输入非空 → 浏览器 JSONP Deezer /search?q=，失败走 /api/deezer?action=search。
  • 联想列表去重后展示；提交时在本地比对歌名 / 艺人。
AppDeezer 搜索 选歌
  • 只消费 Web 权威关卡：GET https://songless.pro/api/game/daily。
  • iOS 不抽 playlist，也不打 Deezer playlist。
搜索
  • ≥2 字符，350ms debounce。
  • 设备直连 GET https://api.deezer.com/search?q=&limit=25。
  • 判题本地。结束后 POST /api/game/daily/attempt。

Archive · 往日 Daily（仅 Web）

Web APIDeezer

选日期 → GET /api/game/archive?date=YYYY-MM-DD → 同一套 ensureDailyChallenge，只允许早于今天。搜索与 Daily 相同（Deezer 远程搜）。App 没有 Archive。

Unlimited / Categories / All Songs

WebDeezer本地抽 选歌
  • 分类目录在仓库 music-categories，每类一组 Deezer playlist ID。
  • 浏览器 loadUnlimitedRound：shuffle 列表，JSONP 拉 /playlist/{id}，丢掉无 preview，避开最近 150 首，随机一首。preview 过期再 /track/{id}。
  • 仍保留服务端 POST /api/game/unlimited/round（同类逻辑），但主路径已是浏览器直连。
搜索
  • 远程 Deezer /search（JSONP → /api/deezer）。
AppDeezer本地抽 选歌
  • 分类来自 App 内 categories-seed.json，禁止再打 /api/game/categories。
  • All Songs 只在 Library。首页横滑是前 8 个分类。
  • loadPlaylistSongs：GET api.deezer.com/playlist/{id}/tracks?limit=100，缓存进内存池，本地 FreePlayRoundSelector 抽。
  • 代码里不允许出现 /api/game/unlimited/round。
搜索
  • 远程 Deezer /search，与 Daily 同一函数 searchSongs。

Survival

Web

就是 Unlimited 引擎 + 3 条命。选歌 / 搜索与 All Songs 相同（Deezer playlist + Deezer search）。局内 lives 本地算。

App

同样用 All Songs 池。lives、第一线索连对加命全在 SurvivalRunState。结束才 POST /api/game/survival/run 换排行。搜索仍是 Deezer 远程搜。

Guess the Artist / Guess The Singer

WebDeezer

answer_mode: 'artist'。曲库仍是分类 / All Songs 的 Deezer playlist。搜索打 Deezer，但结果按艺人去重，UI 只显示艺人名。本地比对艺人而不是歌名。

AppDeezer

UnlimitedGameView(initialCategory: .all, answerMode: .artist)。抽歌同 All Songs。搜索走 Deezer，再 uniqueArtistResults 收成艺人列表。

Artist · 单艺人

iTunes 选歌 · Web
  • 浏览器直接 searchITunesArtistSongs(term, 200, country)。
  • 请求：GET itunes.apple.com/search?term=...&entity=song&limit=200&country=XX。
  • 过滤：必须有 previewUrl；艺人名匹配；去掉翻唱类；按「歌名:艺人」去重。
  • 在池里随机抽下一首，避开已玩过的 track id。
搜索 · Web
  • 不再打 Deezer。 在已下载的 artistSongPool 里本地 includes 过滤，最多 12 条。
找艺人 · Web
  • Artists 页 / Mix 构建器：searchITunesArtists(term, 6~8, country) → entity=musicArtist。
  • 缺头像时再搜一遍 entity=song 用封面当 hint，并把 100x100 换成 1200x1200。
Apple Music 选歌 · App
  • 有 catalogArtistID：GET .../catalog/{storefront}/artists/{id}/view/top-songs?limit=25。
  • 没有：GET .../catalog/{sf}/search?term=&types=songs&limit=25，再按艺人名过滤。
  • MusicKit 发请求。storefront：默认 us，CN→HK，RU→US。
  • 池缓存后本地随机，避开最近 track。
搜索 · App
  • 进了艺人局：在 artistSongPool 本地过滤，不打 Deezer。
找艺人 · App
  • search?types=artists。封面把模板 {w}x{h} 换成 1200。

Artist Mix

选 2–10 个艺人。每个艺人按上面的 Artist 路径拉自己的池（Web=iTunes songs，App=Apple Music top/search）。每回合先随机一个艺人，再从该艺人池抽一首。搜索与单艺人相同：只在合并后的池里本地过滤。

Artist Fan Challenge（仅 Web）

iTunes

开局浏览器 searchITunesArtistSongs(artist.itunes.term, poolLimit, country)，去重后按难度切出 N 首 shuffle。联想搜索用同一池本地过滤。另有服务端 GET /api/game/artist-fan-challenge/rounds 做同样的 iTunes 拉歌，当前主 UI 走客户端直连。

Friend Challenge / 分享挑战

Web 创建

POST /api/game/challenge/create。分类池：服务端 Deezer playlist；艺人池：服务端 iTunes search。被挑战者打开 slug，歌曲已经在挑战对象里，前端不再抽。猜歌搜索：分类挑战走 Deezer 远程搜；艺人挑战走本地池。

App 分享

打完 Daily / Unlimited / Artist 后 POST /api/game/challenge/create 换可分享 URL。App 自己不玩「挑战模式对局」。

Party（可玩的是 App；Web 只做资格接口）

选歌 · App 本地组局
  • 分类：manifest playlist ID → Deezer /playlist/{id}/tracks，凑满 5（Demo）或 10（Plus）首可播放。
  • 艺人 / Mix：Apple Music 拉每个艺人的歌，轮流各取，去重。
  • 没有 /api/party/session/start 出题。Web 上这个接口只回答「有没有 Songless+」。
搜索

Party 不搜歌名。它是传手机、听完亮答案。Web 的 POST /api/party/demo/prepare|consume 只发 / 核销 demoId。

4. 搜索实现对照

场景 Web App
Daily / Unlimited / Survival / Singer 猜歌框 远程 Deezer JSONP /search?q=，失败 /api/deezer?action=search。Singer 模式把结果收成艺人。 远程 Deezer REST /search?q=&limit=25。Singer 再本地 unique 艺人。
Artist / Mix / Fan Challenge 猜歌框 不联网。在本局已经拉到的 iTunes 曲池里对 title / artist 做 normalize + includes，最多 12 条。 不联网。在 Apple Music 曲池里同样本地过滤。
找艺人（目录页、Mix 构建器） itunes.apple.com/search?entity=musicArtist。封面可能二次搜 song 再改 100→1200。 api.music.apple.com/.../search?types=artists，MusicKit。封面替换 {w}{h}。
判题 两边都是本地字符串比对（去音调、大小写、feat./with 拆分）。搜索接口不负责判定对错。

Web 猜歌框分支（heardle-game）

query.trim() 为空 → 清空
若当前是 Artist / Mix：
    过滤 artistSongPool（iTunes 已下载）
    artist 模式只比艺人名
否则：
    searchDeezerTracks(query)   // JSONP → /api/deezer
    artist 模式按 artist.id / 艺人名去重

App 猜歌框分支（Unlimited / Daily）

query.count < 2 → 清空
350ms debounce
若 selectedArtist != nil：
    过滤 artistSongPool（Apple Music 已下载）
否则：
    apiClient.searchSongs(query)  // api.deezer.com/search
    answerMode == .artist → uniqueArtistResults
